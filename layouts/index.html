ONE COHERENT WORKFLOW

从独立编辑，到共同认可的版本。

完成第一次发布
  1. 01

    创建工作区

    基于共享修订开始编辑。一个工作区可以覆盖项目内多个数据集。

    Workspace / Base
  2. 02

    保存与审阅

    要素和字段意图先进入草稿。Diff 展示本次修改，不改动正式数据。

    Save / Diff
  3. 03

    合并与确认

    比较 Base、Current 与 Draft。自动合并独立属性，明确呈现冲突。

    Resolve / Rebase
  4. 04

    原子发布

    正式数据与版本历史共同提交。通过回执确认结果，按修订追溯数据。

    Publish / Revision

DESIGNED FOR SPATIAL DATA

版本管理，不必离开空间数据库。

保留原始坐标与数值精度。
用明确的数据契约，连接编辑器与业务系统。

01 / DATA MODEL

要素级变更，项目级修订

以稳定 ID 跟踪要素，跨数据集组织一次更新。不把整份 GeoJSON 文件当作唯一提交单位。

 02 / POSTGIS

纳管已有业务表

绑定符合约束的原表，保留原始 CRS。正式发布写回原表，版本记录与业务变更共同提交。

 03 / MERGE

让冲突可见、可处理

按属性字段进行三方合并，几何作为整体比较。解决结果与当前 HEAD 和草稿版本绑定。

 04 / SCHEMA

字段定义，也有版本

在工作区组织普通属性字段的新增和删除。按修订读取 Schema，与要素内容保持对应。

 05 / CORRECTNESS

提交有边界，重试有依据

以数据库事务保证发布原子性。响应中断时，沿用原请求 ID 和请求内容确认发布结果。

 06 / HISTORY

追溯过去，而非抹去过去

按固定修订查询历史。撤销某次提交时生成反向工作区，经审阅发布为新的修订。
